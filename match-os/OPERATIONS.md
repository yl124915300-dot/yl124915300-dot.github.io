## 当前最关键的阻碍（严格依次）

1. **商家网络准入**：账户所有人通过官方 <https://agent.livingsocial.com/> 接受已有邀请、激活店铺和创建 Partner API key（**只在私密服务器秘密管理，不传入公共 GitHub 仓库、表单或邮件**）。邮件已向 Groupon 原负责人做过一次精准询问，未见可核实回复，不重复催发。
2. **Groupon 的 CJ 广告主资格**：需独立审核、有效网站 PID 和平台确认归因。没有它，公开 offer 的 `buyUrl` 仅是潜在消费入口，不是 MATCH OS 已有佣金权。
3. **真实购买意向**：只记自愿、非测试的需求；核对商品、规格、预算、地点、时间和用户确认。保留隐私；不把公开讨论/页面访问计为客户。
4. **第一笔结账**：获得适当店铺授权后，先无付款 `catalog → cart → buyLink` 端到端验收；真实买家自行确认并使用商家托管结账。随后核对支付、履约、退款、归因及到账。

## 立即生效的行动规则

- **停止模板式冷邮件、批量外联、重复催促和无实际权限的“先问一问”。** 商家网络不再并行无限扩张；同一条真实阻碍最多保留一个明确负责人和下一动作。
- 每日运营首先查阅**已收到**的官方权限变化及非 QA 买家意向；没有新证据，则不发邮件、不增加模拟订单、不宣称已经成交。
- 邮件只能作为**已存在商务线程的必要回复渠道**，且必须有对方的新问题或确切行动缺口。未经进一步明确授权，自动任务不得主动外发；发件数绝不能是 KPI。
- 任何持续运行的高频撮合必须有已授权真实供给、可用订单/支付事件和合规密钥托管。当前不存在这种生产交易运行状态。
- 失败时记录准确原因（例如无登录、商家未批、无需求、无法结账），只尝试修复阻碍本身。没有数据就不改产品，不以新功能掩盖商业失败。
